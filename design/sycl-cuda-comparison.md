# Warp SYCL vs CUDA: Implementation Decisions

**Status**: Implemented, experimental SYCL coverage; comparison snapshot 2026-10-29

## Motivation

Explain how Warp's Intel SYCL backend preserves the existing CUDA API contracts,
where its implementation differs, and why. "CUDA" below means the existing CUDA
backend in this checkout, based on Warp revision `d5c67074a`; "SYCL" includes the
current local implementation, not just that revision's committed files.
This is an implementation comparison, not a claim of complete CUDA feature parity
or a cross-vendor performance benchmark.

The validated Intel configuration is Arc Pro B70 with oneAPI 2026.1.1 and the
installed, unmodified Level Zero v2 adapter. The more general design and historical
investigations are in [Intel SYCL Backend](./sycl-backend.md).

| Term / label | Meaning in this document |
| --- | --- |
| **Parity** | Preserve a public CUDA-backed Warp behavior using a different backend implementation. |
| **Hardware** | Accommodate Intel device limits or execution-model differences. |
| **Runtime** | Avoid a demonstrated runtime/driver limitation; not necessarily an architectural requirement of SYCL. |
| **Efficiency** | Reduce avoidable work, allocation or synchronization by design. This label does **not** imply a measured speedup over CUDA or an alternative Intel implementation. |
| **Policy** | An application-level capability or launch choice, rather than a GPU kernel rewrite. |
| **Gap** | Deliberately unsupported or less capable in the current Warp backend, not necessarily impossible in SYCL. |
| Uncaptured / eager work | Host-issued operations outside graph capture/replay. This is separate from the compiler/runtime's eager-versus-lazy JIT compilation policy. |
| Event tracing | MuJoCo Warp's `EventTracer`, which measures event timestamp pairs. This is not XPTI, VTune or unitrace system tracing. |
| Captured external event | Warp's `external=True` graph-event behavior. It does not mean importing an external API's event or sharing an event across devices/processes. |

## Design

### Backend, compilation and execution

| Area | Original CUDA implementation | Current SYCL implementation | Why the difference / Intel tradeoff |
| --- | --- | --- | --- |
| Backend identity and dependencies | CUDA devices use CUDA contexts and the runtime/driver APIs in [warp.cu](../warp/native/warp.cu). | Explicit `sycl:N` devices and `Device.is_sycl`; an optional `warp-sycl.so` companion compiled by `icpx -fsycl`. Both build frontends link the Level Zero loader. See [context.py](../warp/_src/context.py), [build_dll.py](../warp/_src/build_dll.py) and [CMakeLists.txt](../CMakeLists.txt). | **Parity / Hardware.** Intel GPU pointers must never enter CPU or CUDA dispatch. Keeping the companion optional avoids requiring oneAPI for CPU/CUDA-only builds; existing default-device selection is preserved. |
| Runtime stack and "v2" | Warp calls NVIDIA's CUDA runtime/driver. | Warp calls DPC++ SYCL, which uses Unified Runtime (UR), its Level Zero adapter, then the Level Zero loader/driver. Adapter selection is left to oneAPI and the user's environment. See [warp_sycl.cpp](../warp/native/warp_sycl.cpp). | **Runtime.** UR is the userspace abstraction below SYCL. "v2" identifies the Level Zero adapter, not a second compiler or kernel driver. Both adapters can ship in the same oneAPI installation; Warp neither patches Intel libraries nor forces v1 or no-lock execution. |
| Device discovery and capabilities | CUDA enumerates NVIDIA devices and queries CUDA attributes. See [warp.cu](../warp/native/warp.cu). | Enumerates Intel GPUs through Level Zero, not duplicate OpenCL entries. Queries work-group/local-memory limits, FP64, 64-bit atomics and graph support. See [warp_sycl.cpp](../warp/native/warp_sycl.cpp). | **Hardware.** Do not assume every Intel GPU has the same capabilities or enumerate one physical GPU twice. Unsupported operations must fail rather than silently run on the CPU. |
| `sm_count`, thread and memory information | Values describe CUDA SMs, CUDA block/thread limits and device memory. | Uses Intel slice/subslice information for the compute-unit count, EU/hardware-thread/subgroup information for a conservative resident-lane estimate, and SYCL memory queries. See [SyclDevice](../warp/native/warp_sycl.cpp) and [Device](../warp/_src/context.py). | **Hardware.** Existing launch-sizing callers need meaningful values instead of zero/stub values. An Xe-core count or resident-lane estimate is an API adaptation, **not** an SM-equivalence, occupancy or throughput guarantee. |
| Kernel code generation and JIT artifacts | Shared Warp codegen emits CUDA kernels; NVRTC produces PTX/CUBIN or link inputs and CUDA loads the result. See [codegen.py](../warp/_src/codegen.py), [build.py](../warp/_src/build.py) and [warp.cu](../warp/native/warp.cu). | Reuses the same generated forward/backward bodies and argument descriptors, adds SYCL `nd_range` launch wrappers, and builds loadable module libraries with `icpx`. JIT compilation lives alongside the CPU/CUDA builders in [build.py](../warp/_src/build.py); native companion compilation lives in [build_dll.py](../warp/_src/build_dll.py). See also [codegen_sycl_module](../warp/_src/codegen.py). | **Parity.** A new launch backend is preferable to a separate kernel language, duplicated autodiff implementation or a MuJoCo-specific kernel fork. This does not select an eager JIT compilation mode. |
| Module cache and device-image identity | CUDA artifacts are selected for the module/options and CUDA target architecture. See [context.py](../warp/_src/context.py). | Separate SYCL artifact names/fingerprints include compiler identity/version, native headers, companion binary and relevant Python builder sources. Kernel tags include the module hash, block dimension and local-storage variant. See [build.py](../warp/_src/build.py), [context.py](../warp/_src/context.py) and [codegen.py](../warp/_src/codegen.py). | **Runtime / Parity.** Prevent stale ABI reuse, CPU/CUDA cache collisions and DPC++ device-image collisions between release/debug or differently sized kernels. This is a correctness fix, not cache-benchmark evidence. |
| Ordinary launch geometry | CUDA launch code computes a grid/block shape and supports grid-stride/lean variants and `max_blocks`. See [wp_cuda_launch_kernel](../warp/native/warp.cu). | Uses a one-dimensional `nd_range`; ordinary kernels round the global size up and bounds-check logical task indices. Launch arguments are captured by value when small enough. See [codegen.py](../warp/_src/codegen.py). | **Parity / Hardware.** A CUDA grid is not a SYCL namespace substitution. Preserve Warp's logical indexing and asynchronous argument lifetime. The current SYCL path accepts `max_blocks` without using it to cap the grid; CUDA thread-block clusters are rejected. |
| Partial logical blocks containing tiles | CUDA has its own block, warp-mask and collective handling in [tile.h](../warp/native/tile.h) and CUDA codegen. | Detects tile use transitively through user functions. Submits full work-groups plus a smaller physical tail group, while preserving the requested logical block dimension and tile register layout. See [codegen.py](../warp/_src/codegen.py) and [sycl_tile.h](../warp/native/sycl_tile.h). | **Hardware / Parity.** Padding a collective kernel and letting some work-items return before a group barrier is unsafe. The smaller tail ensures every physical work-item participates. A nonempty tail can add a second kernel submission. |
| Debug host/device compilation | CUDA device helpers are separated by CUDA compilation guards. | Tile arenas and generated kernel calls are instantiated only in the SYCL device image; common argument captures remain valid in both compilation passes. See [codegen.py](../warp/_src/codegen.py). | **Runtime.** DPC++ also compiles the host closure. Letting that closure reference CPU tile-thread/barrier helpers caused debug module-loading failures. This avoids those references rather than hiding missing symbols. |
| Floating-point options | NVRTC enables `--use_fast_math` only when requested, controls FMA with `--fmad`, and defines `NDEBUG` for release. See [warp.cu](../warp/native/warp.cu). | Without `fast_math`, uses `-ffp-model=precise`, `-foffload-fp32-prec-sqrt` and `-foffload-fp32-prec-div`; disables contraction when `fuse_fp=False`; defines `NDEBUG` for release. See [build.py](../warp/_src/build.py). | **Parity.** The installed compiler's default approximations failed the required simulation/math tolerances. Match the intent of Warp's accuracy options instead of inheriting different compiler defaults. Removing release-only debug checks restores the intended build mode; neither change promises bit-identical GPU arithmetic. |
| Compiler retry workaround | CUDA compilation is unchanged. | Before loading the optional SYCL library, defaults `IGC_DisableRecompilation=1` unless explicitly supplied. See [sycl.py](../warp/_src/sycl.py) and [context.py](../warp/_src/context.py). | **Runtime / Correctness.** Avoids IGC 2.40.13 retry-stage CCD failures while keeping normal release optimization and caching. The setting affects Intel GPU compilation process-wide and may increase spills. A TODO tracks removal after a verified fix; it is not a collision-algorithm rewrite. |
| Device `printf` | Generated device code uses CUDA-supported diagnostic calls. | Emits SYCL device `printf` with a literal format at the generated call site. See [codegen.py](../warp/_src/codegen.py). | **Parity / Runtime.** A generic variadic device wrapper is not accepted on this path. Preserve diagnostics instead of removing error-reporting code or disabling `printf`. |

### Memory, arguments and resource lifetimes

| Area | Original CUDA implementation | Current SYCL implementation | Why the difference / Intel tradeoff |
| --- | --- | --- | --- |
| Array storage and transfers | CUDA device allocations, optional pooled/stream-ordered allocations, and CUDA copies/fills. See [warp.cu](../warp/native/warp.cu). | Arrays use device USM; copies/fills use the current queue. Host readback synchronizes as required, and synchronous host transfers during capture are rejected. Geometry metadata uses shared USM; captured timestamp samples use host USM. See [warp_sycl.cpp](../warp/native/warp_sycl.cpp) and [sycl_runtime.h](../warp/native/sycl_runtime.h). | **Hardware / Parity.** Device USM is not host-dereferenceable array storage, and shared USM is not an excuse for CPU execution. CUDA memory pools/managed-memory semantics are not emulated. |
| Small kernel arguments | CUDA passes argument descriptors through `cuLaunchKernel`. See [warp.cu](../warp/native/warp.cu). | Value-captured descriptors in the SYCL launch closure. See [codegen.py](../warp/_src/codegen.py). | **Parity / Efficiency.** The Python/native caller's stack arguments must remain valid after submission returns. Small arguments avoid a staging allocation/copy. |
| Large kernel arguments | The CUDA path passes the descriptors directly within the target CUDA parameter limits. | A configurable 2048-byte parameter-space budget includes bounds/closure overhead and forward/backward descriptors. Oversized descriptors are copied through USM and the kernel receives pointers; only the selected launch variant is instantiated. See [codegen.py](../warp/_src/codegen.py), [sycl_runtime.h](../warp/native/sycl_runtime.h) and [wp_sycl_stage_args](../warp/native/warp_sycl.cpp). | **Hardware / Parity.** Large MuJoCo `Model`/`Data` arguments exceed the validated Intel limit. Staging preserves the public argument layout instead of rewriting application structs. The budget is an implementation default for this path, not a universal SYCL limit. Descriptors over the current 16384-byte staging limit are rejected. |
| Reusing argument staging | CUDA's ordinary direct-argument path does not need this additional staging ring. | Each stream owns 256 host/device slots of 16384 bytes, allocated lazily. Reuse waits for that slot's prior host-to-device transfer; in-order queue execution protects the device slot. Captured launches get private, graph-retained copies initialized on a separate queue. See [SyclStream and wp_sycl_stage_args](../warp/native/warp_sycl.cpp). | **Efficiency / Parity.** Avoid allocation per uncaptured launch and cross-stream argument corruption. Tradeoffs: staging copies, ring memory, a possible slot-reuse wait, and a blocking initialization copy during capture. Graph replay reuses the captured copy rather than uploading it again. |
| Capture-time array allocations | CUDA records memory-allocation/free nodes when supported and tracks `GraphAllocInfo` so graph/user ownership can overlap. See [warp.cu](../warp/native/warp.cu). | Allocates ordinary device USM during recording and tracks graph/user ownership explicitly. Fill/copy/kernel commands are captured, but Warp does not reallocate that storage on each replay. See [SyclGraphAllocInfo and wp_sycl_alloc](../warp/native/warp_sycl.cpp). | **Parity / Runtime.** Arrays can escape capture and survive graph destruction. SYCL graph-owned allocation lifetime rules are not a drop-in replacement for that contract. A live graph retains all its captured allocations, not just peak-live scratch, so memory use can be higher. |
| Reclaiming graphs, arrays and modules | CUDA tracks graph destruction callbacks and deferred frees/module unloading around captures. See [warp.cu](../warp/native/warp.cu). | Defers physical reclamation while any capture is active; outside capture, waits for relevant stream work before destroying graphs or freeing retained storage/code. Python retains referenced arrays, modules and child graphs. See [run_deferred_actions](../warp/native/warp_sycl.cpp) and [context.py](../warp/_src/context.py). | **Parity.** Avoid use-after-free, invalid synchronization of a recording queue, and dangling generated code. Teardown can wait; this is not a claim that every lifecycle operation is nonblocking. |
| Atomic updates and sub-word storage | CUDA uses native atomic operations where available, with CAS-based fallbacks for some types/operations. See [builtin.h](../warp/native/builtin.h). | Typed `sycl::atomic_ref` CAS loops preserve the old-value return contract, packed half/byte neighbors and unsigned-bit-pattern integer wrapping. Device allocations are padded to whole 32-bit words for sub-word CAS. See [sycl_atomic.h](../warp/native/sycl_atomic.h) and [warp_sycl.cpp](../warp/native/warp_sycl.cpp). | **Hardware / Parity.** Preserve contended updates without assuming CUDA's exact type-specific intrinsics. This is correctness-first, not proof CAS is faster than Intel native atomic-add support. As on CUDA, unique atomic append positions do not imply deterministic record ordering. |

### Streams, events and graphs

| Area | Original CUDA implementation | Current SYCL implementation | Why the difference / Intel tradeoff |
| --- | --- | --- | --- |
| Stream ordering | CUDA streams plus CUDA event dependencies; supports CUDA-specific stream flags and external handles. See [warp.cu](../warp/native/warp.cu) and [Stream](../warp/_src/context.py). | One in-order, profiling-enabled SYCL queue per Warp stream, with a per-device current stream and queue-event dependencies. See [make_queue](../warp/native/warp_sycl.cpp) and [Stream](../warp/_src/context.py). | **Parity.** SYCL queues are not in-order by default. Request ordering explicitly instead of assuming CUDA default-stream rules. CUDA-specific flags/priorities/imported stream handles are not generalized by this mapping. |
| Ordinary event timing | CUDA records events and calls `cudaEventElapsedTime`. | Queue barriers produce ordinary SYCL events; elapsed time uses profiling `command_end` timestamps. See [event functions](../warp/native/warp_sycl.cpp). | **Parity.** `enable_profiling` is necessary for ordinary event timestamps. It does not turn a recording-time graph placeholder into a replay-updated timing marker by itself. |
| Graph creation and adapter capability | CUDA captures streams into CUDA graphs and instantiates executable graphs. See [warp.cu](../warp/native/warp.cu). | Uses the command-graph extension. Supported v2 devices/immediate queues select per-graph `property::graph::enable_native_recording`; other configurations retain the ordinary command-buffer path. [Device.supports_graph_capture, Device.is_graph_capture_event_supported and Device.is_conditional_graph_supported](../warp/_src/context.py) expose ordinary capture, timing and conditional support independently. See [SyclDevice, SyclGraph and wp_sycl_graph_begin](../warp/native/warp_sycl.cpp). | **Runtime / Gap.** Avoid an all-or-nothing "SYCL supports graphs" assumption. Native recording already ships in the validated oneAPI 2026.1.1 runtime; no compiler upgrade, global graph override or adapter patch is required here. |
| Captured timing markers | Python automatically marks timing-enabled events external; CUDA records `CU_EVENT_RECORD_EXTERNAL` during capture. See [Stream.record_event](../warp/_src/context.py) and [wp_cuda_event_record](../warp/native/warp.cu). | Preserves the same automatic external flag. Obtains the immediate native queue handle before recording, then appends barrier / `zeCommandListAppendWriteGlobalTimestamp` / barrier directly during native recording. The graph retains CPU-resident host-USM timestamp slots. See [wp_sycl_event_record](../warp/native/warp_sycl.cpp) and [standalone probe](../tools/sycl_graph_event_probe.cpp). | **Parity / Runtime.** Fine-grained samples must execute on every replay, not at recording time. The tested command-buffer native-callback/native-handle path deadlocked in v2; its callback route under native recording was unsupported. Direct queue recording avoids both paths. This bypasses the old bug; it does not claim that bug was fixed upstream. Host USM avoids migration faults when Python's `faulthandler` replaces the driver's SIGSEGV handler. Each marker adds barrier/timestamp overhead. |
| Timestamp units and replay freshness | CUDA owns event timestamp representation and conversion to milliseconds. | Uses Level Zero timer frequency and valid-bit masks for raw graph samples; ordinary timestamps are nanoseconds. Normalizes mixed pairs and counter wraparound. Every graph replay refreshes marker slots. See [wp_sycl_event_elapsed_time](../warp/native/warp_sycl.cpp). | **Hardware / Parity.** Raw device ticks are not already SYCL profiling nanoseconds. Tests check nested and mixed timing intervals on the validated device; this is not a cross-device clock-synchronization API. |
| Event ownership and re-recording | CUDA runtime event handles and graph event nodes implement the recording/replay relationship. | Each recording owns a sample; graphs retain it independently of later event destruction/re-recording. Replay updates surviving handles to that graph's sample. Dependencies order replays sharing marker storage, including across selected streams and parent/child graphs. See [SyclEventRecord, SyclGraphEvent and wp_sycl_graph_launch](../warp/native/warp_sycl.cpp). | **Parity.** Prevent freed timestamp slots, stale measurements and concurrent writes to shared samples. Serialization is deliberately conservative; it is not an overlap optimization. Completed samples can remain readable after graph destruction. |
| Host event query/synchronization and outside-capture waits | CUDA can query/synchronize an external graph event and make another stream wait on the event's position. See [warp.cu](../warp/native/warp.cu). | Host queries/synchronization are forbidden during capture. Graph-internal events require `external=True` for host access. Before first replay, external queries are incomplete and timing/synchronization errors explicitly. After launch, host waits and outside-capture stream waits use the **containing graph's completion**, not individual marker completion. See [event functions](../warp/native/warp_sycl.cpp). | **Parity / Gap.** Replay samples are real, but completion granularity is coarser than CUDA's marker signaling. Stream waits remain asynchronous. Fine-grained timestamp positions are preserved even though waiting can include the rest of the graph; `synchronize=False` rejects incomplete samples. |
| Waits while capturing | CUDA has native internal dependencies and `CU_EVENT_WAIT_EXTERNAL` for captured external waits. See [wp_cuda_stream_wait_event](../warp/native/warp.cu). | Same-capture waits are supported on the single in-order recording queue, including across retained segments. Captured waits on another graph's events or uncaptured work are explicitly rejected. See [wp_sycl_stream_wait_event](../warp/native/warp_sycl.cpp). | **Gap.** Do not discard `external` or pretend unsupported cross-graph synchronization succeeded. Enabling traced capture does not enable multistream capture or cross-graph external waits. |
| Child graphs captured in a parent | CUDA provides child graph nodes and graph launch/capture machinery. See [warp.cu](../warp/native/warp.cu). | The tested native-recording stack executed a child graph during parent recording rather than retaining it for replay. Warp therefore finishes the preceding native segment, retains the child's segments, and starts the following segment. Replay submits all segments in order on one queue. See [wp_sycl_graph_launch](../warp/native/warp_sycl.cpp). | **Runtime / Parity.** Preserve nonexecution during capture and repeatable nested replay without a driver patch. No host wait is added to replay. Ordinary graphs remain one graph submission; nesting adds submissions at its boundaries and retains child resources. |
| Conditional graphs and advanced capture | CUDA implements conditional graph paths, capture pause/resume and multistream participation. See [context.py](../warp/_src/context.py) and [warp.cu](../warp/native/warp.cu). | Those features are not implemented by the current SYCL backend. Ordinary graph and captured-event capabilities are independent. | **Gap.** A working native-recording path does not establish these other contracts. This is a Warp backend coverage limit, not a statement that all SYCL runtimes can never support them. |

### Tiles, scan and sort

| Area | Original CUDA implementation | Current SYCL implementation | Why the difference / Intel tradeoff |
| --- | --- | --- | --- |
| Warp/subgroup assumptions and local storage | CUDA tile paths use CUDA warp collectives, masks, block barriers and shared storage. See [tile.h](../warp/native/tile.h), [tile_reduce.h](../warp/native/tile_reduce.h) and [tile_scan.h](../warp/native/tile_scan.h). | Queries subgroup width rather than assuming 32. Portable tile paths cooperate across work-items using work-group barriers and a local-memory arena backed by `work_group_static`. See [sycl_tile.h](../warp/native/sycl_tile.h) and the shared tile headers. | **Hardware / Parity.** A CUDA warp, a SYCL subgroup and a work-group are not interchangeable. Avoid copying full-warp masks or lane-index logic onto a different subgroup width; work-group size alone does not force a subgroup size. |
| Local-memory budgeting | CUDA passes dynamic shared-memory requirements to its launch path and has CUDA-specific resource queries. | Estimates the deepest kernel/callee tile frame plus the largest transient tile workspace, with offset/alignment overhead, and rejects modules exceeding the device budget. See [context.py](../warp/_src/context.py) and [tile.h](../warp/native/tile.h). | **Hardware / Efficiency.** Summing all functions' storage rejected valid modules. A maximum follows the arena's stack lifetime instead. The estimate is still conservative and module-wide; it is not per-kernel occupancy tuning. |
| Matrix tiles, Cholesky and triangular solves | CUDA can use libmathdx-backed paths where enabled, and also has first-class portable scalar/cooperative implementations. See [tile_matmul.h](../warp/native/tile_matmul.h), [tile_cholesky.h](../warp/native/tile_cholesky.h) and [tile_solve.h](../warp/native/tile_solve.h). | Reuses those portable implementations on the GPU rather than rejecting them or rewriting MuJoCo's algorithms. No XMX, `joint_matrix` or oneMKL dispatch is added. | **Parity / Gap.** Scalar refers to the arithmetic path, not a CPU fallback or a single-work-item application kernel. This enables correctness now; Intel matrix-engine acceleration remains future work, not an implemented optimization. |
| Array-wide scan | Uses CUB `DeviceScan` with strided iterators and per-component sums. See [scan.cu](../warp/native/scan.cu). | Native three-stage scan: tile reduction, scan of tile sums, then per-tile scans. Supports strided/vector/in-place cases; uses 256 work-items and eight items per work-item. See [scan_sycl.cpp](../warp/native/scan_sycl.cpp). | **Parity / Efficiency.** Keep the operation on the current queue and recordable without introducing a blocking library algorithm. CUB is CUDA-specific; the considered oneDPL paths did not meet the capture/asynchrony contract. Floating-point addition order can differ; exact integer results, not bit-identical floating scans, are the appropriate expectation. |
| Array-wide radix sort | Uses CUB `DeviceRadixSort::SortPairs`, double buffers, requested bit ranges and capture-aware temporary storage. See [sort.cu](../warp/native/sort.cu). | Stable 4-bit LSD passes, signed/float order-preserving key transforms, and ping-pong through the caller's `[n, 2n)` storage. See [sort_sycl.cpp](../warp/native/sort_sycl.cpp). | **Parity / Efficiency.** Preserve Warp's buffer and bit-range API without host sorting or blocking library allocation. The initial 4-bit choice favors simple bounded storage, not proven optimal Intel throughput; full-width 32-bit sorts require eight passes, with irregular scatter traffic. |
| Radix bucket ranking | CUB supplies its own device-specific histogram/ranking machinery. | Each 1024-key tile packs four 16-bit bucket counters per 64-bit word and uses group reductions/scans on the packed words. See [sort_sycl.cpp](../warp/native/sort_sycl.cpp). | **Efficiency.** Reduce the number of separate bucket collectives while preserving stable ranks. The tile-size bound prevents overflow/carry between packed counters. This is a concrete implementation optimization, but no standalone speedup measurement is claimed. |
| Segmented sorting | Uses CUB's segmented radix-sort path. See [sort.cu](../warp/native/sort.cu). | Builds `(segment index, transformed key)` composite keys, stable-sorts once, then gathers/scatters back; uncovered elements stay in place. See [sort_sycl.cpp](../warp/native/sort_sycl.cpp). | **Parity / Efficiency.** Handles unordered/gapped segments without a host loop or one launch per tiny segment. Tradeoff: composite-key storage and sorting all elements, including uncovered ones. Bounds are clamped for memory safety, not a replacement for caller validation or a promise to support overlapping segments. |
| Native algorithm scratch | CUDA sort maintains stream- and capture-aware caches, including side-allocation/graph-allocation paths. See [sort.cu](../warp/native/sort.cu). | Uncaptured work reuses per-stream scratch. Captured operations allocate graph-retained scratch instead of sharing the stream's reusable buffer. See [wp_sycl_scratch](../warp/native/warp_sycl.cpp). | **Parity / Efficiency.** Avoid cross-stream races and captured graphs aliasing mutable scratch. In-order reuse avoids waits in the normal reuse path, but growing uncaptured scratch waits for that stream before replacing its buffer. Captured scratch increases retained graph memory. |
| `tile_sort` algorithm | Bitonic sorting up to 2048 elements and for 64-bit keys; radix path for larger 32-bit tiles. See [tile_radix_sort.h](../warp/native/tile_radix_sort.h). | Work-group bitonic compare-exchanges for all supported lengths that fit local memory; no CUDA shuffle path. Power-of-two lengths sort directly; other lengths allocate padded key/value storage plus validity flags. | **Hardware / Parity.** Avoid fixed 32-lane assumptions and preserve in-place key/value sorting. Validity flags prevent padding from displacing real extreme/special keys. Larger tiles can need more barriers/workspace than CUDA's radix path. Duplicate stability and a particular NaN order are not promised by this tile API. |

### Textures

| Area | Original CUDA implementation | Current SYCL implementation | Why the difference / Intel tradeoff |
| --- | --- | --- | --- |
| Storage and handle ABI | CUDA arrays and texture objects support several dimensions, formats and mip levels. See [texture.cu](../warp/native/texture.cu) and [texture.py](../warp/_src/texture.py). | DPC++ experimental `image_mem` and `sampled_image_handle` implement single-level RGBA32F `Texture2D`. The raw bindless handle fits the existing kernel descriptor and runtime texture arrays. See [texture_sycl.cpp](../warp/native/texture_sycl.cpp). | **Parity / Gap.** Use actual hardware images without accessor-bound kernel signatures, private Python descriptors or a second renderer. Other dimensions/formats, mipmaps and surfaces remain unsupported; this is not complete CUDA texture parity. |
| Sampling and addressing | CUDA texture instructions provide hardware filtering/addressing. CPU has a separate software sampler. See [texture.h](../warp/native/texture.h). | Uses `sample_image` for float/vec2/vec4 results with nearest/linear filtering. Clamp/border allow unnormalized coordinates; wrap/mirror require normalized coordinates. Mixed U/V modes require `ext_oneapi_unique_addressing_per_dim`. | **Hardware / Parity.** Query actual image/format support and reject unsupported modes. The B70 stack does not advertise independent per-axis addressing. There is no software/CPU fallback. CPU nearest-wrap seam behavior differs and is tested against an analytical expectation, not copied into the hardware path. |
| Copies, lifetime and capture | CUDA queues texture copies and retains resources used by captured kernels. | Image copies use the selected in-order queue; cross-stream dependencies use events. Python owners are retained by direct/nested arguments and Python-created texture/struct arrays, including copies/views; capture snapshots the original nested resources. Native release waits for queued users and is deferred during capture. See [sycl.py](../warp/_src/sycl.py), [context.py](../warp/_src/context.py) and [warp_sycl.cpp](../warp/native/warp_sycl.cpp). | **Parity / Gap.** Preserve handle lifetime even after struct-field reassignment or garbage collection. Allocate/copy outside capture and sample on replay. Raw handles/NumPy structured data cannot recover owners. Resource-release synchronization is not a per-render global wait. |

### Geometry and application policy

| Area | Original CUDA implementation | Current SYCL implementation | Why the difference / Intel tradeoff |
| --- | --- | --- | --- |
| BVH/mesh construction and layout | Offers host SAH/median construction as well as GPU LBVH/cuBQL choices, then uses native GPU descriptors. See [bvh.cu](../warp/native/bvh.cu) and [mesh.cu](../warp/native/mesh.cu). | Reuses native host SAH/median builders and C++ layouts, then owns shared-USM copies of the structures. Only those constructors are accepted. See [bvh_sycl.cpp](../warp/native/bvh_sycl.cpp), [mesh_sycl.cpp](../warp/native/mesh_sycl.cpp) and [SyclSharedStorage](../warp/native/sycl_runtime.h). | **Parity / Gap.** Preserve query/layout correctness without Python replicas of private native structs or porting CUDA-only builders prematurely. Construction is explicitly host-backed and synchronizing, not an automatic kernel fallback; shared USM is required. |
| Empty BVHs | The public empty-query behavior must remain safe. CUDA construction has its own empty-tree handling. See [bvh.cu](../warp/native/bvh.cu). | Supplies an empty leaf and valid root when the reused host builder creates no nodes. See [copy_host_tree_to_sycl](../warp/native/bvh_sycl.cpp). | **Parity.** Device queries still dereference the root; copying an absent host root would be invalid. This is a representation fix, not an Intel performance optimization. |
| Ordinary refit | CUDA performs bottom-up BVH refit using leaf work/counters; mesh edge-length processing uses device kernels and scan. See [bvh.cu](../warp/native/bvh.cu) and [mesh.cu](../warp/native/mesh.cu). | Recomputes triangle bounds on the GPU and refits by depth-ordered queue kernels; the average mesh edge-length sum currently uses a single-task GPU loop. BVH launches read a separate host descriptor, not GPU-owned shared-USM metadata. See [bvh_refit_sycl](../warp/native/bvh_sycl.cpp) and [mesh_refit_sycl](../warp/native/mesh_sycl.cpp). | **Parity / Gap.** Queue ordering supplies the inter-level dependency without porting the CUDA counter algorithm first or adding a device-wide wait to every BVH refit. Multiple depth passes and the serial GPU sum are known scalability tradeoffs, not Intel-specific speedups. |
| Winding-number refit | CUDA updates solid-angle properties on the device. See [mesh.cu](../warp/native/mesh.cu). | Synchronizes, reads required arrays back, reuses the host refit and copies updated structures into shared USM. See [mesh_sycl.cpp](../warp/native/mesh_sycl.cpp). | **Gap.** An explicitly host-backed feature, unlike ordinary GPU refit. It cannot run during capture and has transfer/synchronization costs. Callers must also retain geometry resources and avoid mutating topology while captured work uses them. |
| MuJoCo graph capture and event scopes | CUDA uses Warp timing events around unchanged simulation calls and can retain capture while event tracing. | The same event-scoped kernels run on SYCL. MuJoCo checks `device.supports_graph_capture` first and additionally requires `device.is_graph_capture_event_supported` for GPU tracing; otherwise it keeps the uncaptured path. CPU's existing capture policy is unchanged. See [warp_util.py](../../mujoco_warp/mujoco_warp/_src/warp_util.py) and [cli.py](../../mujoco_warp/mujoco_warp/_src/cli.py). | **Parity / Policy.** Capability selection belongs in the application, while replay-visible event support belongs in Warp. `EventTracer` retains its nested `(times, children)` shape; tracing does not require changing JIT policy or rewriting simulation kernels. |
| MuJoCo conditional loops and launch sizing | CUDA can use conditional-graph solver loops and CUDA-sized GPU launch choices. | Keeps conditional-graph capability separate and uses existing fixed-iteration paths where unavailable. GPU-vs-CPU sizing branches include SYCL rather than treating every non-CUDA device as CPU. See [warp_util.py](../../mujoco_warp/mujoco_warp/_src/warp_util.py), [solver.py](../../mujoco_warp/mujoco_warp/_src/solver.py), [constraint.py](../../mujoco_warp/mujoco_warp/_src/constraint.py) and [collision_convex.py](../../mujoco_warp/mujoco_warp/_src/collision_convex.py). | **Policy / Gap.** Preserve the algorithms and avoid accidental serial/CPU launch choices. Fixed iteration counts can waste work relative to a converged CUDA conditional loop; Intel block/subgroup tuning and solver early-exit optimization are not established by this port. |
| Remaining API coverage | CUDA has implementations for additional resources, interop and execution modes. See [native sources](../warp/native/) and [context.py](../warp/_src/context.py). | No current support for texture dimensions/formats beyond the subset above, volumes, hash grids, sparse matrices, indexed arrays, tile FFT, array-wide reductions/run-length encoding, DLPack/external streams, CUDA/SYCL peer copies, deterministic lowering, conditional/multistream capture or graph serialization. See [current limitations](./sycl-backend.md#deliberate-limitations). | **Gap.** Unsupported operations raise rather than route Intel pointers into CUDA or silently compute on CPU. ### Which choices are actually optimizations?

| Choice | Current benefit / reason | Cost or evidence boundary |
| --- | --- | --- |
| Reuse staging slots, stream scratch and native graph recordings | Amortizes allocation/setup and reduces repeated host submission for captures without child graphs. | Large arguments still need copies; scratch growth/slot reuse can wait; nested graphs add submissions. These mechanisms are implemented, but no CUDA-relative speedup is inferred. |
| Packed radix counters and direct power-of-two tile sorting | Fewer bucket collectives or avoided padded scratch, respectively. | Algorithmic savings, not measured optimality. Wider radix digits, better scatter locality and large-tile radix sorting remain tuning candidates. |
| Stack-lifetime local-memory estimation | Stops rejecting valid kernels by summing unrelated frames. | Primarily a correctness/capacity fix, not demonstrated occupancy improvement. |
| Precise math, CAS updates and replay dependencies | Preserve numerical/atomic correctness and prevent sample races. | May cost throughput or overlap. Do not describe them as performance wins merely because they enabled the workload. |
| Direct native timestamp recording and segmented child replay | Avoid observed runtime failures while retaining event timing and nested graph semantics. | Compatibility workarounds, not evidence that native recording or segmentation is faster than CUDA or the ordinary SYCL graph path. |
| XMX/oneMKL/`joint_matrix`, tuned subgroup/block sizes, one-sweep scan, wider radix digits and earlier solver exit | Potential future optimization directions. | **Not implemented or performance-validated by this work.** Measure a correct warmed workload before selecting them. |
